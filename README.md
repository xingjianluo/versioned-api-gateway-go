# 版本化 API 网关核心（本地可验证版）

一个仅依赖 Go 标准库、可在本地完整验证的**版本化 API 网关核心**。业务能力通过
不同的**上游适配器**暴露给调用方；版本协商、分层限流、熔断/降级、有界重试与
回调投递在并发和上游异常下给出**一致且可解释**的结论。

```
pkg/
  version      语义版本解析、兼容策略、可区分的拒绝原因
  upstream     上游适配器接口、按版本/能力匹配的注册表
  ratelimit    调用方层 + 路由层共享的分层令牌桶
  circuit      关闭/打开/半开三态熔断器（半开单探测，防惊群）
  retry        有界指数退避（仅幂等 + 可重试错误）
  idempotency  进程内业务幂等记录（并发同键只执行一次）
  callback     回调/通知 outbox：落盘、去重、有界重放、死信
  gateway      组装上述组件并产出每条请求的决策记录
  errors       统一的可区分错误类型
cmd/demo       无外部依赖的端到端演示
```

## 请求处理流水线

```
版本协商 ──► 分层限流 ──► 版本/能力匹配选路 ──► 幂等去重
                                                      │
   降级兜底 ◄── 有界重试（不跨版本）◄── 熔断判定 ──► 调用上游
```

每一步的判定依据都会写入 `gateway.DecisionRecord` 并打印到日志：
请求标识、版本判定结果、两层配额余额与决策、候选上游、各熔断器状态、
每次尝试的结果/错误类别/是否重试及原因、最终结论。

## 本地验证

```bash
go build ./...
go vet ./...
go test -race -count=1 ./...           # 并发场景开启竞态检测
go test -race -count=5 ./pkg/gateway/  # 稳定性重复
go run ./cmd/demo                      # 端到端演示（无网络/外部依赖）
```

演示会依次展示：正常协商、未知/旧版本拒绝、分层限流配额耗尽、
抖动后兼容集合内重试、持续过载→熔断→降级→半开探测恢复、
回调未确认重放与重复投递幂等、进程重启后的 outbox 重放。

详细语义见 [docs/design.md](docs/design.md)。
